# Signal Taxonomy

Use only the approved categories below unless a human explicitly approves a new category.

## 1. Stakeholder

Use for conditions involving:
- champion strength;
- weakened champion;
- leadership change;
- missing decision-maker;
- unclear decision ownership;
- technical validator;
- operational owner;
- gatekeeper;
- stakeholder misalignment.

## 2. Proof / Value

Use for conditions involving:
- ROI proof;
- reporting proof;
- sample validation;
- pilot result;
- success criteria;
- measurable value;
- proof not converting into a decision.

## 3. Technical

Use for conditions involving:
- PMS / CRM integration;
- data availability;
- internal BI;
- implementation complexity;
- tracking / attribution setup;
- technical validation;
- reporting architecture.

## 4. Commercial

Use for conditions involving:
- budget;
- pricing;
- procurement;
- legal;
- MSA;
- commercial approval;
- rollout timing;
- scope economics.

## 5. Adoption

Use for conditions involving:
- product usage;
- internal socialization;
- stakeholder adoption;
- workflow fit;
- rollout behavior;
- value being used but not recognized.

## 6. Risk / Blocker

Use for conditions involving:
- unresolved blocker;
- loss of urgency;
- unclear success criteria;
- weak proof;
- cancellation risk;
- implementation concern;
- competing priority;
- no clear path to next decision.

## Signal Record Structure

Every candidate signal must include:

- **Signal Type**
- **Observed Condition**
- **Deal Context**
- **Impact in This Deal**
- **Evidence**
- **Transferability**
- **Confidence**

## Context Preservation Rule

Do not store a signal as a universal statement.

Bad:

`Internal BI = risk.`

Good:

`Technical — Internal BI existed as a strong internal alternative in this deal; it increased the burden of proving differentiated value.`

A different deal may show internal BI as an integration opportunity. Preserve the original context.
